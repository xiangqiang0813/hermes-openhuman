# 记忆系统详细设计文档

## 整体架构设计

本系统采用四重保障机制确保记忆系统的稳定性和效率：

### 1. 指纹去重机制
- **全局指纹**：使用 SHA256 对完整记忆内容生成唯一指纹
- **逐项指纹**：对记忆中的每个条目单独计算指纹
- **替换策略**：发现重复时直接替换而非追加
- **归档联动**：旧版本自动归档到历史记录

### 2. 时间控制策略
- **更新间隔**：严格控制在1小时间隔，避免过度频繁同步
- **增量更新**：只处理新增或修改的内容
- **定时触发**：通过 Hermes cronjob 定时执行更新任务

### 3. Token预算管理
- **硬预算限制**：固定 4000 token 上限
- **智能淘汰**：超出预算时自动裁减最旧的记忆
- **压缩优化**：对长文本进行智能压缩处理

### 4. 存储架构
记忆文件存储在 `~/.hermes/archive/daily/` 目录下：
```
~/.hermes/archive/daily/
├── 2024-01-01.md
├── 2024-01-02.md
├── ...
└── current.md (当前活跃记忆)
```

## 记忆文件格式规范

每个记忆文件采用简洁的 Markdown 格式：

```markdown
# 记忆概览 [YYYY-MM-DD HH:mm:ss]

## 今日摘要
- 用户偏好：喜欢简洁直接的回答风格
- 重要事件：完成了项目A的需求评审
- 待办事项：准备下周的技术分享

## 详细内容
<此处为详细的记忆条目，每行只保留最新状态>
```

## 淘汰机制实现

当总 token 数超过 4000 时：

1. **统计阶段**：计算当前所有记忆的 token 总数
2. **识别阶段**：找出最早添加的记忆条目
3. **移除阶段**：按时间顺序逐步移除最旧条目
4. **平衡阶段**：直到总 token 数回落到 3800 以下

这个过程确保记忆始终保持精炼且相关。
